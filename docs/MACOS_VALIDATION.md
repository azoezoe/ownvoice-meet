# Mac 驗證記錄（2026-11-22）

環境：Apple Silicon arm64、macOS 26.2。此分支是 Zoe Meet 0.2.4 的第一個 Mac 測試版。

已完成：

- `npm run build` 與 `npm run typecheck` 通過。
- 前端 8 個測試檔、29 個測試通過。
- Rust 64 個測試通過；12 個需要硬體或真實 API 的既有測試預設略過。
- 新增 CoreAudio Float32 交錯／分離聲道轉單聲道的測試，以及停用／短音訊緩衝區的邊界測試。
- 實際開啟 Mac App；字幕 Demo、回覆視窗、講稿與設定顯示正常，Command 快捷鍵文字正確。
- 確認 Mac 的講稿隱藏功能不再顯示成保證有效，改為提醒只分享需要展示的視窗。
- App 使用獨立 bundle ID；API key 啟用原生 macOS 鑰匙圈後端，不沿用上游的鑰匙圈服務名稱。
- 更新來源指向自己的 fork，上游更新簽章公鑰已移除。
- 使用者完成首次授權後，在交付的 `releases/Zoe Meet.app` 執行系統聲音 6 秒檢查，播放本機 440 Hz 測試音；UI 明確顯示「Mac 系統音訊：已收到電腦聲音，可以開始」。
- 同一交付版本的預設麥克風 6 秒檢查完成，MacBook Pro 麥克風成功開啟並回傳音量，當時環境聲被判定為偏小。介面的最大音量整數百分比四捨五入顯示為 0%，這不代表未收到音訊；該結果與收音啟動逾時、沒有送出任何聲音的錯誤不同。
- 上述收音短測沒有儲存音檔、未呼叫雲端服務。

尚待完成的實機檢查：

- 雲端辨識、翻譯與中文回覆：未填入或使用個人 API key，未呼叫付費服務。
- 實際 Zoom／Teams 長時間會議、AirPods、切換音訊裝置與 Intel Mac 尚未驗證。
- 本版使用 ad-hoc 簽章，沒有 Apple Developer ID 公證；簽章包已綁定 Info.plist 與麥克風 entitlement。

首次授權曾因 TCC 等待 App 進入前景而延後顯示，完成使用者授權後重測已通過。收音檢查只量測本機音量；不將音訊存檔、不送到雲端。完成授權後，先在設定按「電腦聲音檢查」，播放已知的音訊，確認顯示「已收到電腦聲音」，再測試麥克風。更換輸出裝置後，先停止聆聽再重新開始。
